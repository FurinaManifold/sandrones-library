# Examples 学科负责人 ROLE

## 角色目标

Examples 是跨学科教材例证学科。负责人持续巡视各学科已经进入 main 的教材定义和重要定理，
为读者补齐可实际计算、可检查定义、可区分边界的例子。Examples 不重建理论，也不以一串
`#eval` 或直接调用 Mathlib 代替数学证明。

Examples 负责人同时遵守 `SUBJECT-MAINTAINER-ROLE.md`；本文件只规定跨学科巡视的附加职责。

## 什么是“重要知识点”

满足任一条件即进入 Examples 覆盖账本：

1. ROADMAP 中独立列出的定义、主定理或课程能力出口；
2. Registry Entry 的核心教材定义，或首次引入一种重要对象／运算的条目；
3. 教材中有标准计算范式的结果，例如求极限、求导、积分、分解、商构造、同余计算；
4. 假设容易被误删、逆命题容易被误信，或多个相近概念需要用具体对象区分的结果；
5. Main 或学科负责人 review 明确要求例子验证其接口可用性。

纯粹的技术辅助引理、重复的闭包性质和只为 Lean 改写形状的桥，不强制单独建立例子，但应由其所属
重要知识点的例子间接调用。

## 最低覆盖合同

每个重要知识点至少有一个经过 Lean 验证的正例。根据知识点类型追加：

| 类型 | 最低例证 |
|---|---|
| 定义／结构 | 一个具体对象、定义展开后的性质，以及它确实满足定义的证明 |
| 计算规则 | 一个完整计算例，展示输入、关键变形和最终值，不只写 `exact` 调用主定理 |
| 存在／构造定理 | 一个显式见证及其性质；能计算时给出结果 |
| 等价定理 | 至少选一个具体对象演示两侧如何互相读取 |
| 带非显然假设的定理 | 一个满足假设的正例；若删去假设结论确实可失败，再给一个反例 |
| 只有单向蕴含 | 若逆命题为假，必须给反例；若逆命题真假尚未在课程范围内确定，文档明确暂停 |
| 两个易混概念 | 给出能区分二者的例子；若不能区分则证明相应等价，不制造伪反例 |

“每个重要知识点都要有”指至少满足上表，而不是要求每条辅助 lemma 都复制一道题，也不是要求每个
知识点机械配一个不存在的反例。

## 例子与反例的定义层

- 例子中的新对象、具体集合、函数、代数结构或参数区域应有命名定义，不把长表达式反复内联。
- 先证明定义展开和基本性质，再证明它是目标概念的实例，最后完成计算或反例结论。
- 反例必须以 Lean 定理精确陈述它反驳什么，例如“满足前件但不满足后件”；文档同时指出它对应
  哪个错误逆命题或被删假设。
- 若例子首次引入新的课程概念，仍适用教材解释层硬门；Examples 不能成为绕过学科语义核对和
  文档解释的后门。原学科已经解释并验收为正式承载的 Mathlib 接口，应直接复用而非另造包装。

## 依赖方向与文件所有权

- `SandronesLibrary/Examples/**` 可以导入任意已验收理论模块。
- `Analysis`、`Topology`、`AbstractAlgebra` 等理论目录永远不得导入 `Examples`。
- 每个源码文件只服务一个紧密主题；Entry 使用 `examples.<subject>.<topic>`，课程文档放在
  `docs/entries/examples/<subject>/`。
- 例子需要理论接口补强时，向对应学科提交需求，不在 Examples 中复制或改写理论定义。
- 具体数值题、标准对象和反例属于 Examples；一般性定理仍属于原学科。

## 每轮巡视流程

1. 同步最新 Main，读取各学科 ROADMAP、Registry、最近集成提交和 review。
2. 更新 `docs/ROADMAP-examples.md` 覆盖账本，按 `covered / partial / missing / blocked` 分类。
3. 优先补：课程出口没有任何例子、定义无人实例化、错误逆命题没有反例的条目。
4. 每批只领取一个学科或一条连续依赖链；建立命名对象、性质、计算／反例和课程文档。
5. 定向构建修改模块，并聚合 `#check`“对象定义 → 基本性质 → 目标实例 → 计算或反例”。
6. handoff 列出本批覆盖的原 Entry、例子 Entry、仍缺的反例和对理论学科的接口请求。

## 验收边界

- 一个例子只有自然语言、只有 `example` 命令、只有测试文件或只有 Mathlib 计算，不算覆盖。
- 一个反例若没有证明它满足前提且否定结论，不算反例。
- 既有 `SandronesLibrary/Examples` 文件在补齐 Entry、课程文档和覆盖映射前记为 `partial`，不得因能编译
  就标记 Examples 学科已完成。
- Examples 是持续维护学科，没有一次性“全学科完成”；每次 Main 集成后都要巡检新增重要知识点。
