# 动机
序数把彼此同构的良序视为同一个“排列形状”，从而可以比较不同集合上的良序。

# 直觉
序型忘掉元素叫什么，只保留先后关系；自然数通常序的序型记作 `ω`。

# 陈述（自然语言）
两个良序的序型相等，当且仅当二者序同构；自然数通常严格序的序型是 `ω`。

# 陈述（Lean 对照）
`orderType_classification` 同时给出 `Ordinal.type r = Ordinal.type s ↔ Nonempty (r ≃r s)` 与自然数序型公式。

# 思维脉络（thinking trace）
`Ordinal.type` 是良序按序同构取商后的对象，因此相等恰好由序同构刻画；自然数一式由标准构造直接计算。

# 从“排队方式”理解序型

设想三种排队：

1. 三个人排成 `甲 < 乙 < 丙`；
2. 三本书排成 `上册 < 中册 < 下册`；
3. 集合 `{7, 20, 100}` 按通常大小排列。

三者的元素完全不同，但都具有“第一个、第二个、第三个，并且到此结束”的同一种次序形状。
序型就是把元素姓名、材质和数值全部擦掉，只留下这个形状。三个例子的序型都是有限序数 `3`。

无限情形更能说明区别。自然数按 `0<1<2<⋯` 排列得到 `ω`。把同一个集合改成
`1<2<3<⋯<0`，也就是把 `0` 放到所有正整数之后，所得序型是 `ω+1`，不再是 `ω`。
所以序型记录的不只是“有多少元素”，还记录它们怎样良序排列。

# 为什么必须要求良序

良序的含义是：每个非空子集都有最小元。整数的通常次序不是良序，因为全体整数没有最小元；
实数的通常次序也不是良序，例如正实数集合没有最小正数。序数只刻画良序，因为超限归纳需要
“若反例存在，就能挑出最小反例”这一关键步骤。

Lean 中 `Ordinal.type r` 把良序关系 `r` 取序同构等价类。`Ordinal.type_eq` 正是在说：
两个代表给出同一个序数，恰好意味着它们之间存在保持并反映次序的双射。

# 应用与陷阱
- 序数比较的是良序结构，不等同于只比较底集基数；`ω` 与 `ω+1` 都可数，但不是同一序数。
- “线性序”不自动等于“良序”；必须检查每个非空子集有最小元。
- 序同构要求双向保持次序，不是任意双射。
