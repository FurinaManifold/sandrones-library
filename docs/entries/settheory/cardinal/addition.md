# 要解决的问题

有一批 `α` 类对象和一批 `β` 类对象，怎样描述“把两批都收进来以后共有多少个”？有限情形中
我们会直接把两个数相加；但对一般集合，首先必须说明“合在一起”是哪一个集合构造。

# 为什么普通并集不够稳妥

如果直接取两个集合的并集，共有的元素只会出现一次。例如 `{红, 蓝}` 与 `{蓝, 绿}` 的并集
只有三个元素，而“第一批有两个、第二批也有两个”本应得到四个位置。基数加法不应该因为两批
对象碰巧使用了相同名字就少算一项。

解决方法是先贴标签：第一批的 `a` 写成 `inl a`，第二批的 `b` 写成 `inr b`。即使 `a` 与
`b` 原来是同一个对象，左右标签也使 `inl a` 和 `inr b` 成为不同元素。这样的合并叫不交并。

# 定义

```lean
def CardinalSum (α : Type u) (β : Type v) := Sum α β
```

因此 `|α|+|β|` 的含义，是类型 `Sum α β` 的大小，而不是先调用一个已经存在的基数加法运算。
`Sum α β` 的每个元素恰好有两种形状：`inl a` 或 `inr b`。

# 有限例子

设 `α` 是三种上衣，`β` 是两种帽子。`CardinalSum α β` 表示“从上衣或帽子中选一件”，共有
`3+2=5` 个选择。这里不是同时选上衣和帽子；“同时选”对应下一条基数乘法。

若 `α` 为空，那么不交并只剩右边，故 `0+|β|=|β|`。若两边各只有一个元素，则左右标签
产生两个不同元素，故 `1+1=2`。

# 无限情形为何看起来反直觉

自然数与另一份贴了标签的自然数合并后仍然可数：可以把左边第 `n` 项编成偶数 `2n`，右边
第 `n` 项编成奇数 `2n+1`。所以无限基数可能满足 `ℵ₀+ℵ₀=ℵ₀`。这不表示定义中丢掉了
一边，而是存在一个双射把两份可数对象重新排成一列。

# 定义与等势代表无关

基数只关心大小，不应依赖我们给元素起什么名字。若 `α` 与 `α'` 等势，双射 `e : α ≃ α'`
可在不交并左半边使用，右半边保持不动，于是得到
`Sum α β ≃ Sum α' β`。形式化定理 `cardinalSum_respects_equinumerous` 正是在验证这一点。

# 自然语言 ↔ Lean

- 不交并 ↔ `Sum α β`。
- 左边的一项 ↔ `Sum.inl a`。
- 右边的一项 ↔ `Sum.inr b`。
- 替换一个等势代表不改变和的大小 ↔ `cardinalSum_respects_equinumerous`。

# 常见混淆

- 基数加法使用不交并，不是可能重叠的普通并集。
- “二选一”对应加法；“各选一个并组成一对”对应乘法。
- 无限情形的结果可能等于某个加数，但定义仍然是完整的不交并。
