# 动机

写出 `H_λ(n)=H_{λ[n]}(n)` 并不等于定义了 Hardy 层级，因为式中的 `λ[n]` 还没有含义。对极限记号 `λ`，必须先选定一列更小的记号 `λ[0],λ[1],…`。不同记号系统或不同基本列约定可能产生不同的具体函数，因此这项数据不能藏在符号背后。

# 直觉

可以把层级记号看成路线牌。零记号说“已经到底”；后继记号指向自己的前一站；极限记号没有唯一前一站，于是随自然数 `n` 给出第 `n` 条下行路线。合法性检查至少要保证每条路线确实向下，而不是绕回当前站或跑到更高处。

# 陈述（自然语言）

一个基本列系统由记号类型、严格下级关系和分类函数组成。分类函数对每个记号返回三者之一：零；带一个前项的后继；带函数 `ℕ → 记号` 的极限。系统合法是指：后继的前项严格低于它，极限基本列的每一项也严格低于该极限。

# 陈述（Lean 对照）

`FundamentalStage ι` 的三个构造子分别是 `zero`、`successor previous` 和 `limit sequence`。`FundamentalSystem ι` 保存 `below` 与 `stage`。`FundamentalSystem.Legal` 对分类结果逐项表达下降条件，定理 `fundamentalSystem_legal_rules` 将该条件公开为可直接使用的规则。

# 思维脉络（thinking trace）

先把“极限时取基本列”从层级函数中拆出来，才看得清哪些是记号系统的数据，哪些是递归定义。随后只规定最低限度的局部下降条件。这足以解释每次计算为什么选择较低记号，但还不足以推出递归一定在全域终止，因此后面的可执行定义另带有限燃料。

# 自然语言 ↔ Lean 映射

“记号”对应类型参数 `ι`；“严格低于”对应 `system.below`；“前一站”对应 `previous`；“第 `n` 个基本列项”对应 `sequence n`；“所有递归出口向下”对应 `system.Legal`。这里没有使用序数加法、乘法或幂，也没有把 Mathlib 的现成增长层级改名包装。

# 依赖（人话版）

本条只依赖自然数作为基本列下标。它不依赖已经开发的序数运算，也不声称 `ι` 中的记号已经覆盖所有小于 `ε₀` 的序数。若要得到经典全域层级，还需证明下级关系良基，并补充基本列的单调性、共尾性和极限记号覆盖性质。

# 应用与陷阱

这个接口是 Hardy 与快速增长层级共同的输入。最大陷阱是把 `λ[n]` 当成天然唯一：例如 `ω` 常取 `ω[n]=n`，但更复杂极限的基本列依赖规范。另一个陷阱是仅有“每项更小”便宣称完成全域递归；局部下降不自动提供整个关系的良基证明。
