# 动机

Knuth 记号把“运算等级”写成箭头数量，例如一支箭头是幂，两支箭头是迭代幂。Conway 的链式箭头把这个想法再推进一步：参与递推的数据不再只有底数、箭头数和右参数，而是一整条有限正整数链。因此，开始讨论递推公式以前，首先必须严格回答“一条链是什么”以及“最短的链怎样求值”。

# 直觉

可以把 `3 → 4 → 2` 看成三张依次排列的卡片，而不是把箭头当作普通二元运算。链的长度会参与后续递推，所以括号化成 `(3 → 4) → 2` 会丢失原记号的本意。最短的两种情形没有这种歧义：一项链 `a` 的值就是 `a`，两项链 `a → b` 的值是 `a^b`。

# 陈述（自然语言）

一般 Conway 链被定义为一个非空有限自然数列表，并要求列表中的每一项都为正。为了不给未完成的一般递推披上“已经可执行”的外衣，本条另设长度不超过二的受限链：它要么是 `a`，要么是 `a → b`。受限求值分别返回 `a` 和 `a^b`，并有单独的合法性谓词检查输入是否为正。

# 陈述（Lean 对照）

`ConwayChain` 保存 `entries : List ℕ`、非空证明和逐项正性证明，是任意有限链的公开语法。`ConwayShortChain` 只有 `singleton` 与 `pair` 两个构造子；`Valid` 表达正性，`toChain` 把合法的受限链嵌入一般语法。`eval` 给出受限求值，`conwayShortChain_equations` 逐字证明一项、两项两条计算方程。

# 思维脉络（thinking trace）

先把语法与语义分开：列表负责保存链的原始形状，求值函数才负责解释它。然后检查完整 Conway 递推的终止性要求；其递归调用会同时改写链尾和生成新的中间参数，不能靠一次普通的列表结构递归草率通过。于是本批固定一个可验证的小接口，先完成不会争议的基本情形，把一般良基递归留给后续专门证明。

# 自然语言 ↔ Lean 映射

“有限链”对应 `List ℕ`；“至少有一项”对应 `entries ≠ []`；“每项为正”对应 `positive` 字段。`a` 对应 `.singleton a`，`a → b` 对应 `.pair a b`，而“它们的值分别为 `a` 与 `a^b`”对应 `ConwayShortChain.eval` 的两个定义分支。`toChain` 只忘掉长度限制，不进行求值。

# 依赖（人话版）

只依赖自然数、有限列表和自然数幂。本条没有调用 Mathlib 的大数记号实现，也不依赖本库的 Knuth 上箭头；二项链的幂是 Conway 记号自身的基本约定，而不是从其他大数记号偷渡来的定义。

# 应用与陷阱

这个接口足以让后续条目安全地保存任意有限链，并计算最短两类例子。它尚不能计算三项或更长链，也没有形式化 Conway 的一般递推方程、终止性和与 Knuth 记号的对应。尤其不能把 `.pair a b` 当成普通箭头计数，也不能声称本条已经实现 Graham 数之外的完整 Conway 层级；这些都是明确留给下一阶段的边界。
