# 1　项目定位：把数学知识变成可追溯的工程资产

**Sandrone’s Library 项目介绍**\
**重点：自然语言与 Lean 的对应验证，以及论文形式化的 Multi-agent 工程流程**

本项目在 Mathlib 的基础上建设可扩展数学库。一个数学知识点同时拥有中文教材解释、Lean 定义或定理，以及 Registry 中的身份、依赖、来源和公理记录。它希望让读者既能理解“这个结论在说什么”，又能检查“代码究竟证明了什么”，并让下一批形式化工作复用已经验收的知识。[S1–S3]

本文依据 **Main `b2cd090c9208283ccd3c2f3740bcece3e3f0d6ea`** 的文件与现场只读检查撰写。2026-10-10 重新统计得到 565 个 `verified` Entry、694 条直接教材依赖边、73 条 BibTeX 来源、317 个关联 Lean 文件，覆盖 11 个条目家族。这里的 `verified` 是 Registry 登记状态；本次没有重新执行全库验收，不能据此发布新的 Main 验收快照。

| 项目资产 | 保存内容 | 对论文形式化的价值 |
|:---|:---|:---|
| `SandronesLibrary/` | 正式定义、引理、定理及证明 | 可编译、可被后续证明调用的知识 |
| `docs/entries/` | 八段教材说明与自然语言—Lean 映射 | 供数学审阅者核对意义与强度 |
| `index/registry.json` | Entry 身份、依赖、来源、公理、文件指纹 | 追溯某结论来自哪里、依赖什么 |
| `reference.bib` | 统一维护的出版物级来源 | 连接原论文、条目与证明 |
| ROLE、Playbook、handoff、review | 文件所有权、工作方法、交接与验收记录 | 支持跨会话、跨 Agent 持续推进 |
| `docs/world-formula/` | 消费已验收资产的自然语言综合书稿 | 提供逐断言审稿的现有实践 |

项目的核心价值是**可解释的形式化知识组织，以及有明确责任边界的交付流程**。语义一致的 Mathlib 对象可以直接成为正式承载；只有教材概念与现成对象确有差异时，才建立本库定义和具名桥。成熟工具的复用与教材层的解释可以同时成立。

已有能力包括 Entry 组织、依赖图、编译、公理查询、结构审计、独立 worktree 和分层验收。论文级声明账本、自动任务调度、环境绑定的验证收据和覆盖报告，是本文基于这些机制提出的工程扩展，**尚未在当前仓库中实现为统一系统**。

**阅读路径。** 第 2–4 页解释对应关系如何验证；第 5 页限定“论文验证”的范围；第 6–7 页给出多 Agent 分工与工程契约；第 8 页以路线图中的真实论文候选演示拆解；第 9–10 页说明验收、已知缺口和实施顺序。本文提供设计方案，没有启动新的论文证明批次。

# 2　验证的核心：证明正确、转写准确、覆盖完整

Lean 的基本检查对象是一个命题及其证明项。可概括为：在环境 $\Gamma$ 中，检查证明项 $p$ 的类型是否为命题 $P$，即 $\Gamma\vdash p:P$。Tactic 帮助构造证明项，最终仍须通过内核检查。此机制建立的是**给定形式化命题在所披露基础与依赖下成立**的证据。[E1–E2]

自然语言没有同样的确定语法。原文说“收敛”，可能指逐点、一致、依概率或弱收敛；说“相等”，可能指逐点相等或几乎处处相等。Lean 不会自动判断作者选的定义是否表达了原文意图。因此需要三道分别验收的门。

| 验收门 | 核心问题 | 主要证据 |
|:---|:---|:---|
| A　语义对应 | Lean 命题是否准确表达原文？ | 原文定位、量词与假设表、定义解释、独立审稿 |
| B　形式证明 | 该 Lean 命题是否有合格证明？ | 编译结果、完整公开签名、实际公理依赖、禁用占位检查 |
| C　范围覆盖 | 承诺验证的论文内容是否全部闭环？ | 冻结的声明清单、逐项状态、证明责任和未覆盖说明 |

只有 B 通过，可能只是证明了原结论的特例或更弱版本；A、B 通过但 C 未完成，则只能报告已经验证的声明范围。三者不应压缩成一个含混的“已验证”。

## 对应关系具体核对什么

审核时先读签名，再读证明。逐项检查：**对象与类型、量词次序、显式和隐式假设、结论方向、等号含义、取值范围、边界情况**。例如 `∀ x, ∃ y` 允许见证依赖于 `x`，`∃ y, ∀ x` 要求同一个见证适用于全部 `x`；`[CompleteSpace E]` 虽是类型类参数，也是一项数学前提。[S3、S6]

当两侧都已形式化，应在明确的对象转换下核对量词绑定，证明条件 $H\leftrightarrow H'$，并在共同条件下比较结论 $C\leftrightarrow C'$；只有单向桥时，应披露限制或推广方向。**两个定理都可证后，再证明它们逻辑等价，并不足以证明忠实转写**，因为两个真命题本就等价。真正要审核的是对象、前提和结论各自的意义。自然语言到首个正式命题的解释责任仍由语义审核承担。

## Mathlib 概念的四类归属

公开接口中首次出现的专用对象，归为：（1）语义一致的正式承载；（2）本库特殊定义的桥侧接口；（3）私有证明后端；（4）语义未解释或越出课程范围的公开泄漏。前三类都要披露，第四类需要修改或 Main 明确批准。每个核心概念还要具有定义解释、正式承载、展开或刻画、必要桥、真实上层使用者，以及准确 Entry 归属。[S2–S3]

`#print axioms` 报告当前证明路径的依赖，包括经典选择、命题外延性和商类相关基础。它不能证明这些公理对该数学结论“不可避免”，也不会代替语义审核。允许哪些基础应明确记录；自定义额外公理与未证明占位不能被藏在“编译成功”背后。[E3]

# 3　真实案例：如何核对 ε–N 收敛定义

仓库中的 `analysis.sequence.definition` 提供一个完整且易检查的例子。正式源码为 `SandronesLibrary/Analysis/Sequence.lean`，教材文档为 `docs/entries/analysis/sequence/definition.md`。[S7]

**教材意思：** 对实数列 $u$ 与实数 $l$，无论给出多小的正误差 $\varepsilon$，都能找到自然数起点 $N$，使此后每一项与 $l$ 的距离小于 $\varepsilon$。

```lean
def SequenceConvergesTo (u : ℕ → ℝ) (l : ℝ) : Prop :=
  ∀ ε > 0, ∃ N : ℕ, ∀ n ≥ N, |u n - l| < ε
```

| 教材中的片段 | Lean 中的对应 | 要排除的错误 |
|:---|:---|:---|
| 实数列、实数极限 | `u : ℕ → ℝ`、`l : ℝ` | 把对象层级或数域换掉 |
| 任意正误差 | `∀ ε > 0` | 漏掉正性，或只检查某一个误差 |
| 存在起点 | `∃ N : ℕ` | 把存在换成固定常数 |
| 此后全部项 | `∀ n ≥ N` | 只检查一个项或一段有限样本 |
| 距离严格小于误差 | `|u n - l| < ε` | 把绝对值或不等号方向写错 |

这里最关键的是 **$N$ 可以依赖于 $\varepsilon$，不能依赖于随后选择的 $n$**。若误写成 $\exists N,\forall\varepsilon>0,\forall n\ge N$，则尾部每项与 $l$ 的距离必须小于所有正数，在实数中意味着尾部恒等于 $l$；这比通常的收敛强得多。编译器可以检查错误版本的证明，却不会提醒作者“你换了教材概念”。

## 从定义到桥，再到实际使用者

源码先给出 `sequenceConvergesTo_iff_epsilon_N`，以定义展开保证公式与谓词一致；再用 `Metric.tendsto_atTop` 和 `Real.dist_eq` 证明：

```lean
theorem sequenceConvergesTo_iff_tendsto {u : ℕ → ℝ} {l : ℝ} :
    SequenceConvergesTo u l ↔ Tendsto u atTop (𝓝 l)
```

最后，`sequenceConvergesTo_unique` 真正接受两个教材收敛假设，经过桥转换后使用滤子极限唯一性，得到两个极限相等。这形成可审核的链：**教材定义 → 公开展开 → Mathlib 等价桥 → 上层公开定理**。桥在 Lean 中证明两个正式表达等价；教材文字与第一个公式之间的对应由上表和独立审阅确认。

本次对 `SandronesLibrary.Analysis.Sequence` 的模块及依赖闭包进行了定向构建，并用临时聚合文件 `#check` 上述定义、两条桥及唯一性使用者。探测编译退出码为 0；桥与唯一性使用者实际公理依赖均为 `propext`、`Classical.choice`、`Quot.sound`。这验证了该案例的正式接口，范围不等于整库或整篇论文。

# 4　将对应验证变成可重复执行的审核过程

建议为每个论文声明建立一份**语义对齐记录**。它连接原文、规范化数学陈述、Lean 公开类型和审核结论，防止“代码修好了，中文悄悄变了”或“摘要写强了，定理没有跟上”。以下是建议新增的论文级机制，当前 Entry 文档提供了可复用的基础。

## 五步语义核验

**第一步：冻结来源与声明。** 保存论文版本、原始文件哈希、页码、定理或公式编号、必要上下文和符号说明。PDF 物理页码与印刷页码分别记录；OCR 提取需回看原页。不得由 Agent 补造原文没有的参数或定理编号。

**第二步：先冻结数学契约。** 在证明之前列清对象、所有量词、前提、结论、相等方式和边界。省略的假设分为“原文上下文可恢复”“为当前子范围明确增加”“无法判定”。后两类不能默默写成原论文已经证明的事实。

**第三步：核对 elaboration 后的公开类型。** 用 `#check`、`#print` 和必要的 `pp.all` 检查隐式参数、实例与强制转换。依赖常量也须追到实际定义；只看简短打印类型不足以发现 notation、范数实例或局部 instance 的语义变化。签名修改需要新一轮语义审核。

**第四步：独立回译与挑战。** 审阅者先读原文和正式签名，独立写出“Lean 这句话用数学语言是什么意思”，再与作者说明比较。对照空集合、零维、零分母、不可测函数、退化方差等边界；尝试给过强或错误逆向找反例。有限测试只能发现问题，不能证明一般语义等价。

**第五步：绑定证据与版本。** 审核记录绑定原文版本、声明、源码提交、公开类型及相关环境、公理与编译收据。作者修复后，审阅者逐项复验；不能把旧审核结论直接沿用到修改后的签名。

还须排除空洞通过：是否把待证结论本身加入前提？是否把目标包含在结构字段中？是否增加了无法满足的假设？例如从 `h : P` 得到 `P` 是合法证明，但若原文没有 `h`，它就没有完成原任务。真实使用者及非退化实例可以揭示这类问题，仍不能取代逐项语义核验。

| 对齐记录字段 | 应记录的事实 |
|:---|:---|
| 来源定位 | 论文哈希、原文页码与编号、上下文范围 |
| 数学契约 | 对象、量词、假设、结论、边界 |
| Lean 映射 | 全限定声明名、实际类型、承载与桥 |
| 关系分类 | 忠实对应／明确限制／明确扩展／待澄清 |
| 证明路线 | 原证明结构、现代证明或现成结果复用 |
| 审核证据 | 审阅者身份、发现、处理结果、复验提交 |

仓库已有《水仙十字的世界式》逐断言审稿机制：检查对象、量词、假设、方向、状态、来源和边界，再做结构编辑审核，最后由 Main 一致性验收。论文工作流可复用这套责任分离。[S8]

**独立角色的价值与限度。** 非作者审阅和先回译再比对，可以减少作者解释带来的锚定。不同 Agent 仍可能使用同一模型、相同提示或同一资料，错误可能相关；“三个 Agent 都同意”没有自动增加数学保证。最终仍需逐项可追溯的语义判断，以及 Lean 检查的正式证明。

# 5　“一篇论文形式化”首先是一份范围契约

项目纳入协议的输入可以是一篇论文中的指定结论，过程为分解、双语转写、形式化、校验和注册。路线图进一步规定：论文应逐批下沉到已验收课程基础中，每批交付 3–6 个相互支撑、能被下游使用的公开声明，并记录所采用的证明路线和未覆盖部分。[S4–S5]

**论文不是单一 theorem。** 一篇论文可能含定义、主定理、辅助引理、算法、实验、解释性讨论与隐含背景。启动前必须把这些内容列成声明清单，确定哪些属于本次证明责任。只有完成冻结范围内的逐项覆盖，才可报告该范围的形式化完成。

| 声明类别 | 形式化或验证任务 | 不能混同的结论 |
|:---|:---|:---|
| 数学定义、主定理、推论 | 建立正式对象并证明相应命题 | 定理存在不等于原证明过程被重建 |
| 证明中的必要步骤 | 分解证明责任，披露复用的已有结果 | 调用最终定理不等于验证其内部论证 |
| 算法与复杂度 | 数学算法规范、正确性及成本模型 | 实数模型正确不等于浮点实现正确 |
| 数值实验或统计结果 | 代码、数据与实验协议的可复现检查 | 实验复现不等于普遍定理证明 |
| 解释、历史与应用判断 | 来源核验与适用范围说明 | 不能强行改写成已证明的 Lean 结论 |

## 三种应分别报告的目标

**结果形式化：** 证明论文某个数学结论，可以采用现代等价证明，也可以复用已经披露且语义匹配的 Mathlib 结果。**论证重建：** 还要把原论文关键推理步骤逐项对应到正式引理。**算法实现验证：** 在数学定理之外，另建立程序语义、数值误差或成本模型的桥。三者的交付物和工作量不同。

声明清单应包括：原文位置、依赖、目标范围、承载、证明路线、负责人、当前证据与未完成责任。已有库结果可作为外部已验证依赖，但应披露依赖边界；若声称重建原证明，则仍须覆盖其承诺的关键步骤。不能通过删掉困难引理，把覆盖率提高到 100%。

建议定义冻结范围 $S$，其中当前版本完成语义与证明双验收的声明集合为 $V$，报告 $|V|/|S|$；同时单列主定理状态、证明责任闭环情况、明确限制和未纳入内容。若某主定理依赖仍未闭环，大量简单条目的完成不能抵消这个缺口。论文版本变化或范围调整必须保留前后记录。

## 开发门与论文候选状态

当前路线图将论文候选分为 `paper_ready`、`paper_research_open`、`future_paper`。`paper_ready` 表示必要设施已进入 Main，可建立首批 RFC；正式开发仍须分配所有权。后两类分别允许研究调查或只登记未来依赖门。不能因为 Mathlib 存在相近最终 theorem，就跳过本库尚未完成的课程承载与接口解释。

论文级完成报告应使用明确措辞，例如“已完成第 2 节三个指定结论的结果形式化，采用现代证明，未覆盖原文实验及唯一性讨论”。这类限定使成果可以被下一批可靠复用。

# 6　Multi-agent 分工：围绕依赖与审核组织并行

本库已有“子 Agent → 学科负责人 → Main”的三级验收。子 Agent 只交付自己的模块；学科负责人亲自审核数学、接口、文档、依赖闭包和联合导入，收敛成单一批次；Main 接收学科交付、更新共享状态，完成全库验收。[S2–S3、S9]

论文任务可以沿用这个结构，新增只读语义审阅与论文覆盖汇总职责。以下角色是工程设计中的职责划分，不意味着必须同时启动同样数量的进程。

| 角色 | 输入与输出 | 写入边界 |
|:---|:---|:---|
| 论文负责人／学科负责人 | 声明清单、冻结签名、任务 DAG、批次 handoff | 所属学科分支与论文交接材料 |
| 定义与接口 Agent | 承载、刻画、必要桥、上层调用框架 | 独立定义模块及对应 Entry 初稿 |
| 证明 Agent A／B | 已冻结引理契约 → 无占位证明与局部收据 | 互不重叠的证明模块 |
| 语义审阅者 | 原文＋实际类型 → 对齐发现和复验结论 | 自有审核记录；不代改作者源码 |
| 边界／实例审阅者 | 假设挑战、反例、接口实例化需求 | 交接给 Examples；正式例子由其负责 |
| 验证执行器 | 精确提交＋命令 → 日志、公理与退出码 | 隔离构建目录与收据 |
| Main | 已验收批次 → 共享状态与最终集成提交 | 主工作树、Registry、路线图与派生数据 |

![建议的论文任务流；共享写入与最终验收仍由 Main 负责。](workflow.pdf){width=100%}

**依赖驱动的工作顺序：** 原文声明冻结 → 定义和签名冻结 → 上层组装类型检查 → 无相互依赖的引理并行证明 → 学科联合验收 → 独立语义审核闭环 → Main 集成。公共定义有一个写者；下游不能各自猜一个版本再等待合并时修补。

每个写入型 Agent 使用独立 worktree 和分支；仅仅给多个 Agent 指定不同文件，仍不足以隔离 Git index、未提交文件和构建缓存。调度器必须把执行目录随任务传递，构建输出写到该 worktree。共享依赖缓存只有在只读发布、版本绑定且不会被并发更新时才适合复用；正式构建产物不能靠多个写者共享目录获得。

**一个批次的并行安排。** 负责人先验收定义层；再让 Agent A 和 B 分别证明两个不互相依赖的引理链；只读审阅可在签名稳定后进行。下游组装必须使用负责人明确接收的接口提交。资源有限时串行审核、并行最小模块编译，不让所有 Agent 重复全库构建。

这里的独立性有两层：文件与运行环境的隔离保证工程可控；作者与审阅者的责任分离帮助发现语义错误。两层都不能仅靠“多开几个聊天窗口”实现。负责人的验收记录和 Main 的最终提交，才把分散输出转化为可交付资产。

# 7　工程契约：任务、调度、返工与失效传播

建议增加确定性的论文任务控制器。LLM 负责理解、转写、提出证明和分析报错；控制器负责依赖就绪判断、所有权、状态迁移和证据完整性。控制器不能通过解析 Agent 的“完成了”一句话决定任务通过。

## 任务输入必须绑定可重现的事实

任务契约至少包括 `task_id`、原文声明 id 与定位、Main 基线、依赖提交、冻结的数学契约与 Lean 签名、独占文件、允许的 Mathlib 角色、构建命令、预期公开声明、审阅者以及失败处理。输出包括候选 commit、实际改动文件、日志、退出码、公理结果、语义发现与逐项处理记录。

可在论文侧增加以下目录，作为建议而非当前已实现功能：

```text
docs/papers/<slug>/
  scope.json          声明清单、覆盖范围、排除项
  alignment.jsonl     原文与 Lean 的逐声明对齐
  tasks.json          任务 DAG、所有权与签名版本
  receipts/           编译、公理、语义复验收据
  coverage.md         当前覆盖与未完成边界
```

这些字段不能擅自加入现有 Registry。Registry 的 Entry 状态继续使用 `verified/pending/unresolved`，Main verdict 继续使用既有四值。建议的调度状态另存：`extracted → contract_frozen → ready → proving → locally_checked → staged → integrated`；语义审核结果为独立字段，`staged` 前必须完成负责人验收与审核闭环。失败用阻塞原因或返工状态记录。

## 调度与返工规则

控制器可用 SQLite 事务管理领取记录：一次领取同时绑定任务、路径所有权、签名版本、依赖版本和心跳租约。租约超时只说明需要检查 worker；必须确认原进程已停止或收回写入能力，才能把路径交给新 worker。旧进程仍能写文件时直接重新派工，会破坏独占性。

调度只选择依赖与权限都满足的任务；完成后检查提交范围、收据和审核记录。Registry 的 `premises` 是教材依赖图，任务 DAG 还须记录实际 imports、证明调用及接口提交，不能直接照搬教材边。连续五次同一子证明失败时，按 Playbook 拆成更小框架，并先让上层调用新接口通过类型检查。`sorry` 框架只留在 `/tmp/sandrones-library/<run>/<task>/`，正式源码不接收占位。超时、依赖缺失、语义歧义与证明失败分别记录。[S3]

Main 的返工通知写入仓库外 `review-inbox`；学科负责人逐项记录 `resolved`、`declined with reason` 或 `still blocked`。复验后收敛进 Git 内 review。仅文档规范问题由 Main 整理，不能冒充数学返工。

**失效传播。** 建议用 SHA-256 绑定源码与规范化公开类型、依赖提交、相关实例及 simp 环境、Lean 版本、`lake-manifest.json`、构建选项和命令。签名、定义或环境改变时，相应证明、语义记录及下游收据标为待复验；纯证明体改变可保留原语义契约，但仍需重跑受影响证明与公理检查。当前 `proof_sha` 只是源码文件的短 SHA-1 指纹，不能承担全部环境绑定责任。[S10]

# 8　论文案例：Eckart–Young 低秩逼近怎样拆成任务

路线图已把 Eckart–Young（1936）的低秩逼近论文列为 `paper_ready` 候选，首批范围为有限维矩阵的截断 SVD、误差公式与最佳秩 $k$ 逼近。出版者页面确认论文书目信息和最小二乘矩阵逼近主题。[S5、E4]

**本页是实施设计，不是论文验证完成报告。** 本次核验了书目信息、路线图与本库 SVD 源码，没有逐页读取原论文全文。以下使用现代数学表述说明任务拆解；原文页码、编号、原证明结构及每项对应关系，必须在实际立项时补齐并审核。首批建议限定实矩阵；复数推广单独登记，避免冒充原文范围。

## 冻结一个准确的主结论

取 $A\in\mathbb R^{m\times n}$，$d=\min(m,n)$，$0\le k\le d$。将奇异值按 $\sigma_0\ge\cdots\ge\sigma_{d-1}\ge0$ 排列，由同一份 SVD 证书构造截断矩阵 $A_k$。明确使用

$$
\|A\|_F^2=\sum_{i=0}^{m-1}\sum_{j=0}^{n-1}|A_{ij}|^2.
$$

目标是证明 $\operatorname{rank}(A_k)\le k$，以及对每个同尺寸、$\operatorname{rank}(B)\le k$ 的矩阵 $B$，

$$
\|A-A_k\|_F^2=\sum_{i=k}^{d-1}\sigma_i^2
\quad\text{且}\quad
\|A-A_k\|_F^2\le\|A-B\|_F^2.
$$

此表述要求最佳性相对于**全部**秩受限候选，而不是有限样本；没有声称最佳矩阵总是唯一，也没有声称任意酉不变范数的推广。项目现有 `operatorNorm` 是诱导算子范数，不能把它静默当作 Frobenius 范数。[S11]

| 任务 | 交付与前置依赖 | 责任分工 |
|:---|:---|:---|
| D　承载与定义 | 矩阵—线性映射桥、Frobenius 平方、截断定义；复用现有 SVD 证书 | 定义 Agent，负责人先验收 |
| L1　截断秩界 | 从截断表示证明 `rank ≤ k`；依赖 D | 证明 Agent A |
| L2　误差公式 | 正交展开、范数关系与尾和；依赖 D | 证明 Agent B |
| L3　任意候选下界 | 对任意秩受限 B 建立误差下界；先冻结独立契约 | 后续独立证明任务 |
| T　最佳逼近组装 | L1、L2、L3 → 主结论及非空候选实例 | 负责人联合导入验收 |

现有 `MatrixSVD.lean` 已有分解证书、矩阵分解和奇异值—秩接口，是可用基础；本次目标源码搜索没有找到项目自有的 Frobenius 最佳低秩逼近声明。因此 SVD 入库与这篇论文核心结论入库应分别报告。L3 的下界是独立证明责任，不能只完成截断构造和误差公式就宣称最佳性。

Examples 另验 $k=0$、$k=d$、零矩阵、矩形矩阵和重复奇异值。$A=\operatorname{diag}(1,1)$、$k=1$ 时，保留任一坐标都给出相同误差，可用于揭示“总是唯一”的误读；一般唯一性条件不进入本批承诺。

# 9　验收流水线：从局部证明到 Main 与论文报告

仓库的责任分层可以直接用于论文批次。以下命令来自当前规程；模块构建、公理记录、语义审核和论文覆盖各自保留证据，不能互相替代。[S2–S3、S9–S10]

**子 Agent 门。** 在自己的 worktree 编译最小修改模块；在隔离临时文件内查询新增公开声明、公理和必要实例。扫描 `sorry/admit/sorryAx/native_decide` 与额外公理。文本搜索只是辅助，仍需核对正式声明和真实依赖。通过后提交自己的文件与局部验证记录。

**学科负责人门。** 复查每个核心概念的定义—刻画—桥—使用者链；编译批次全部模块及依赖闭包。临时聚合文件联合导入并 `#check` 关键声明，必要时增加实际调用，检查实例冲突与组合兼容性。确认独立语义审核的问题已经处理，并写成一个 handoff。负责人不运行全库 `lake build`。

**Main 门。** 核对基线、提交、所有权与语义 diff；接收数学合格提交，再整理共享文档、imports、Registry、文献和 Examples 需求。按照 AGENTS 的顺序运行：

```bash
python3 scripts/extract_registry_references.py
python3 scripts/update_dependency_graph.py
python3 scripts/gen_entries_index.py
python3 scripts/gen_entry_rankings.py
python3 scripts/check_axioms.py --all --fix
python3 scripts/check_axioms.py --all
python3 scripts/audit.py
git diff --check
lake build
```

公理探测依赖已构建的导入模块；学科闭包与 Main 的必要定向重建应确保探测对应当前源码。默认公理检查会增量跳过匹配指纹的文件，不能报告为全部声明刚刚重新探测。需要独立全量复验时使用 `--full`，具体范围由验收计划记录。最终完整 `lake build` 只由 Main 在共享集成完成后执行。

## 验证收据与最终验收包

每次命令保存执行目录、提交、Lean 与依赖版本、命令参数、开始结束时间、退出码、日志哈希、被检查声明和范围。区分进程失败、查询解析失败、警告与合格结果；任何“跳过”都需要说明原因，不能替代通过。保留实际 linter warnings，不把要求写成当前已经“零警告”。

最终包包括：论文版本与范围清单、逐声明对齐记录、Lean 源码提交、关键公开类型、证明路线、依赖和公理报告、局部与 Main 构建收据、语义审核闭环、覆盖表、复现指令和未完成边界。Main 提交后的下一批必须同步最新 Main，再重跑受影响接口。

统一 verdict 为 `accepted`、`accepted_main_docs`、`needs_changes`、`blocked`。`accepted_main_docs` 只表示数学通过、Main 规范整理尚未完成；它既不意味着论文所有声明都完成，也不意味着最终 Main 集成已经完成。论文覆盖结论必须另外绑定具体范围与最终提交。

# 10　现场发现、实施顺序与证据索引

项目已有可复用的知识资产与协作规程；推进论文工作流的关键增量，是补齐**声明范围、语义对齐、自动调度和环境绑定证据**。现有文档中的协议目标应与当前脚本能力分别阅读。

## 本次现场取得的证据与局限

`audit.py` 对 565 条记录检查通过。源码显示它主要检查 id、路径、文件存在、部分 front matter、BibTeX 字段、依赖 DAG 和反向缓存；**没有实现一般自然语言—Lean 语义判定、完整签名等价检查或实际证明依赖提取**。例如 ε–N 条目文档的 `kind` 为 `definition`、`mathlib` 为两个名字，Registry 则为 `theorem`、空列表，此差异没有阻止审计通过。它说明字段核验有缺口，不说明该条 Lean 桥证明错误。[S7、S10]

565 条记录中，563 条 `proof_sha` 与关联源文件当前短指纹匹配；另两条为 `linear-algebra.vector-space.dimension`、`real-analysis.riemann.cont-integrable`。未匹配应触发定向检查，不能直接判断数学真伪。本次强制复验了 ε–N Entry 的公理，另对桥和使用者进行了接口探测；没有重新运行全库验收，也没有修订既有条目。

部分旧文档仍提到正式文件 `#exit` 后可保留草稿、较强的自动审计能力或零警告要求。执行时以当前 AGENTS 和 Playbook 的硬门为准：占位草稿隔离到 `/tmp`，数学审核不能被结构审计替代。`check_axioms.py` 当前使用固定临时 probe 路径；自动并行执行前应改成任务隔离路径，或先串行化该步骤。

## 建议按四个可验收增量实施

1. **声明账本与对齐试点。** 选一个已解锁候选，冻结 3–6 项公开声明；来源定位、语义关系、排除项和未完成责任全部可追溯。
2. **结构检查与收据。** 严格解析并比较 front matter；导出实际 Lean 类型与声明映射；对缺声明、解析失败和缺日志明确失败；绑定源码及依赖环境。结构检查仍不宣称自动解决语义理解。
3. **多 Agent 控制器。** 实现 DAG、独立 worktree、唯一文件写者、任务隔离临时路径、租约与失效传播；复验通过的提交才进入负责人 handoff。
4. **完整批次演练。** 在相同冻结范围和资源记录下比较单 Agent 与多 Agent 的耗时、失败、返工和未覆盖责任；完成 Main 集成与论文覆盖报告后再讨论效率收益。本次未测得性能提升。
